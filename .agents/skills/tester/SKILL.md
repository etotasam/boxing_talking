# Tester

## Purpose

- 実装詳細ではなく、公開される振る舞い、仕様、ユーザーから見える結果を検証する。
- 変更リスクに応じて必要なテストだけを追加・更新する。
- 関連テストを実行する。実行を省略する場合は `When Test Execution Can Be Skipped` に従い、省略した場合や実行できない場合は理由を報告する。

## Workflow

1. 変更内容が保証すべき振る舞いを整理する。
2. `正常系` `異常系` `境界系` から必要な観点を選ぶ。
3. フロントエンドのテスト作成・更新時は `.agents/skills/frontend-test/SKILL.md` を読む。
4. バックエンドのテスト作成・更新時は `.agents/skills/backend-test/SKILL.md` を読む。
5. 関連テストを実行し、必要に応じて lint / build / coverage も確認する。テスト実行を省略する場合は `When Test Execution Can Be Skipped` に従う。
6. Plan Document に基づく作業では、担当するテスト・検証タスクの完了後、
   該当する Tasks を `- [x]` に更新する。
   未実施・未確認の事項が残るタスクは完了扱いにしない。
   未実施・省略したテストや検証タスクはチェックを付けず、該当項目に理由を記載する。
   併せて、`docs/plans/README.md` の対象計画の進捗を更新する。
7. テスト結果、保証した内容、残リスクを報告する。

## When to Add Tests

- 認証、フォーム送信、API 通信を変更した場合。
- validation、状態分岐、例外処理、一覧取得、ページングを変更した場合。
- 既存テストで変更後の振る舞いが保証されていない場合。

## When Test Execution Can Be Skipped

以下の場合は、変更内容とリスクに応じてテスト実行を省略できる。
省略した場合は、その理由を報告する。

- ドキュメントのみの変更。
- 表示文言やスタイルのみの軽微な変更。
- 既存テストで同じ仕様が十分に保証されており、変更がその振る舞いに影響しない場合。

テスト実行を省略する場合も、変更に応じた差分確認などの検証は行う。
