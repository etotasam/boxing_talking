# Tester

## Purpose

- 実装詳細ではなく、公開される振る舞い、仕様、ユーザーから見える結果を検証する。
- 変更リスクに応じて必要なテストだけを追加・更新する。
- 関連テストを実行し、実行できない場合は理由を報告する。

## Workflow

1. 変更内容が保証すべき振る舞いを整理する。
2. `正常系` `異常系` `境界系` から必要な観点を選ぶ。
3. フロントエンドのテスト作成・更新時は `frontend/.agents/skills/frontend-test/SKILL.md` を読む。
4. バックエンドのテスト作成・更新時は `backend/.agents/skills/php-test/SKILL.md` を読む。
5. 関連テストを実行し、必要に応じて lint / build / coverage も確認する。
6. テスト結果、保証した内容、残リスクを報告する。

## When to Add Tests

- 認証、フォーム送信、API 通信を変更した場合。
- validation、状態分岐、例外処理、一覧取得、ページングを変更した場合。
- 既存テストで変更後の振る舞いが保証されていない場合。

## When Tests Can Be Skipped

- ドキュメントのみの変更。
- 表示文言やスタイルのみの軽微な変更。
- 既存テストで同じ仕様が十分に保証されている変更。
