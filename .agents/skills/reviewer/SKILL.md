# Reviewer

## Purpose

- 実装差分が依頼内容と承認済み方針に合っているか確認する。
- バグ、仕様漏れ、不要な変更、テスト不足を優先して指摘する。
- 指摘を増やすこと自体を目的とせず、問題がない場合は無理に改善点を作らない。
- 問題がない場合も、未実行テストや残リスクを明示する。

## Review Assignment

- レビュー担当は `AGENTS.md` のエージェント選択ルールに従う。
- 小規模タスク（単一ファイル・単純修正）は、メインエージェントがこのスキルを参照して実装後のレビューを行う。
- それ以外の変更、Planner の設計案レビュー、明示的に依頼された git diff / PR / 実装差分のレビューは、Reviewer subagent が担当する。

## Checklist

- 要件と実装が一致しているか。
- 無関係な変更や生成物の編集が含まれていないか。
- 型、安全性、例外処理、境界値に問題がないか。
- レビュー対象にフロントエンド実装が含まれる場合は `.agents/skills/frontend-review/SKILL.md` を参照し、React / TypeScript 固有の観点を確認する。
- バックエンドでは認証、認可、validation、DB 変更、エラーコードに問題がないか。
- テストが公開される振る舞いを検証しているか。
- lint / build / test の実行結果が報告されているか。

## Plan Document Completion

Plan Document に基づく作業の最終レビューでは、対象の計画と [Plan Document Template](../../../docs/plan-document-template.md) を参照し、以下を行う。

1. `Tasks` の各項目について、実装・必要な検証が実際に完了しているか確認する。チェック済みであることだけを根拠に完了と判断しない。
2. 修正が必要な指摘が解消され、最終レビューが完了したら、該当するレビュータスクを `- [x]` に更新する。未実施・未確認のタスクは完了扱いにせず、チェックを付けない。
3. 未チェックのタスクが残る場合は、該当項目に未実施・省略の理由が記載されていることを確認し、内容と理由を示して archive への移動についてユーザーの判断を求める。許可を得るまでは移動しない。許可されても未実施タスクのチェックは付けず、全タスク完了とは扱わない。
4. 全タスクの完了を確認した場合、または未チェックのタスクを残した移動をユーザーが許可した場合、Reviewer subagent が対象文書末尾の `Outcome` に、実施内容・検証結果・最終レビュー結果・残課題や未確認事項を記載する。未チェックのタスクがある場合は、未実施事項・理由・archive 移動の許可も記録する。対象外の事項や後続課題と、今回のタスクの未完了を区別する。
5. `Outcome` 記載後、対象文書を `docs/plans/archive/` 配下の適切な分類ディレクトリへ移動する。適切な分類がない場合は、移動時に分類ディレクトリを新規作成する。元の日付・ファイル名は維持する。
6. `docs/plans/README.md` の「現在の計画・保留事項」から該当項目を削除する。「履歴一覧」は分類ディレクトリへのリンクに集約し、個別文書のリンクは追加しない。新しい分類を作成した場合のみ、その分類へのリンクと概要を追加する。
7. 未解決事項や再評価条件がある場合は現在の入口へ引き継ぐ。文書移動に伴う参照リンクを更新し、相対リンク・見出し参照の不整合がないか確認する。

## Output

- 指摘は重大度順に並べる。
- 各指摘には対象ファイル、理由、修正方針を含める。
- 指摘がない場合は「問題なし」と明記する。
- テスト不足と残リスクを分けて報告する。
