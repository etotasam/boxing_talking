# 作業名

## Goal

この作業の目的と、どうなれば達成したと判断できるかを書く。

## Background / Context

判断に必要な背景や前提条件がある場合に記載する。
現状、問題点、修正や新機能が必要になった理由、設計の前提などを書く。
Goal と重複する説明だけになる場合は、この節は省略する。

## Scope

- 対象：今回対応すること
- 対象外：今回対応しないこと

## Impact Area

影響する可能性がある機能と、ユーザーから見える動作を書く。
関連する別機能への影響があれば記載する。
具体的なファイル名の記載は必須としない。

## Approach / Rationale

採用する方針と、その理由を書く。
合理的な選択肢が複数ある場合は、比較と採用理由も記載する。

## Tasks

- [ ] 実装タスク
- [ ] 必要なテスト・動作確認
- [ ] Reviewer subagent による最終レビュー

実施・確認が終わったタスクだけを完了にする。
未実施・省略したタスクはチェックを付けず、該当項目に理由を記載する。

## Test Plan

- 何を保証するために、どのテスト・動作確認を行うかを箇条書きで記載する。
- テストを不要と判断する場合は、その理由を記載する。

## Risks

- 想定されるリグレッション、注意点、確認上の制約を箇条書きで記載する。
- 特になければ「特になし」と記載する。

## Outcome

未実施。
