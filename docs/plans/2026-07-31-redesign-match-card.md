# Compact Fight Poster Match Card

## Goal

ホームと過去試合一覧で共用する `MatchCard` を、試合詳細ページと同じ黒・金・赤青コーナーのテイストを持つ、コンパクトなファイトポスターへ変更する。

- 選手名は既存の日本語 `name` をフルネームのまま主表示する。`engName` を表示・分割しない。
- タイトル団体の数だけ、`VS` の上に金色の星を表示する。団体名や `TITLE FIGHT` はカードに表示しない。
- 日付、階級、試合会場を表示する。カードは試合詳細ページへの入口であり、詳細なタイトル情報や投票操作は個別ページで扱う。
- DB、API、管理フォーム、既存データの変更は行わない。

## Background / Context

現行の `frontend/src/components/module/MatchCard.tsx` は、左右の `BoxerBox` と中央の `MatchInfo` により、英字名・国旗・日本語名・階級・タイトル団体・日付を3カラムで表示している。

この構成には、長い日本語名を `・` で分割して末尾だけを表示するロジックがある。たとえば `ホスベル・ペレス` を `ペレス` としてしまうため、選手名の識別性を損ねる。また、タイトル戦では WBA/WBC/IBF などの団体名と試合グレードを表示しており、一覧カードとしては情報が細かすぎる。

カードの対象は、次に見る試合を選ぶ閲覧者である。カードの仕事は「誰と誰が、いつ、どの階級で、どこで戦うか」と「いくつのタイトルが懸かるか」を短時間で伝え、押下後に個別試合情報ページを読んでもらうことである。個別ページには団体名、詳細な試合情報、勝敗予想があるため、一覧ではそれらを重複させない。

### Design Tokens

| 種別 | 値 | 用途 |
| --- | --- | --- |
| Canvas | `#111214` | ページ背景 |
| Card | `#1B1D20` | カード面 |
| Name Ivory | `#F5F2E9` | 選手名。純白ではなく、わずかに黄みを持つ主表示色 |
| Secondary | `#AAA8A1` | 補助的な罫線・情報 |
| Championship Gold | `#D99A2B` | `VS`、星、外枠、会場アイコン |

- 日本語選手名は `M PLUS 1p` の太字、または既存の日本語フォントスタックの太字を使う。新しいフォント読み込みは不要とする。
- `VS` と日付は、すでに読み込み済みの `Bebas Neue` を使う。日本語名には適用しない。
- シグネチャーは、中央の `VS` とその上の星列とする。カード外枠は角丸を付けず、背景画像、団体ロゴ、王冠、赤青コーナーラインは追加しない。

### Layout Contract

```text
PC
┌────────────────────────────────────────────────────────────────┐
│ 🇺🇸                         ★ ★ ★                         🇬🇧 │
│ ジェシー・ロドリゲス             VS             サニー・エドワーズ │
├────────────────────────────────────────────────────────────────┤
│ 2026.08.30 SUN    │ バンタム級        │ 📍 T-Mobile Arena   │
└────────────────────────────────────────────────────────────────┘

SP (320px)
┌────────────────────────────────────┐
│ 🇺🇸          ★ ★ ★          🇬🇧 │
│ ジェシー・ロドリゲス VS サニー・エドワーズ │
├────────────────────────────────────┤
│ 2026.08.30 SUN  │ バンタム級        │
├────────────────────────────────────┤
│             📍 T-Mobile Arena       │
└────────────────────────────────────┘
```

- 左選手の国旗は、名前の上かつ左端に寄せる。右選手の国旗は、名前の上かつ右端に寄せる。
- 選手名は省略・姓名分割をせず、既存の `name` を1つの文字列として扱う。
- 星の個数は `matchData.titles.length` と一致させる。星は「タイトル数」のみを示し、WBA/WBCなど個別団体の意味は試合詳細ページで提示する。
- 下段は PC では日付・階級・会場の1行、SPでは日付・階級の1行と会場の1行とする。日付は英語短縮曜日を大文字で付けた `YYYY.MM.DD DDD` 形式（例: `2026.08.30 SUN`）とし、時刻は表示しない。階級は既存の日本語値に `級` を付ける。
- `venue` が空文字または空白だけの場合、会場行・会場区切りを表示しない。`会場未定` のような未登録値をカードで捏造しない。
- PCのメタデータ帯は、会場ありでは日付・階級・会場を3等分し、会場なしでは日付・階級を2等分する。各項目の中身は中央寄せにする。SPの日付・階級も2等分して中央寄せとし、会場はその下の全幅行で中央寄せにする。
- 既存の `VoteIconForTop` が表示される場合、アイコンはカード左上から `12px` の位置に固定する。左選手ブロックはアイコン幅 `25px` と間隔 `8px` の合計 `33px` を開始側に予約し、国旗と名前をその予約領域の右から同じ左端に揃える。アイコン非表示時の予約幅は `0` とする。320pxでも国旗・名前・アイコンを重ねない。

## Scope

### In Scope

- `MatchCard` の構造と Tailwind class を、左右選手ブロック・中央 `VS`/星・下段メタデータ帯へ置き換える。
- 選手名の主表示を `BoxerType.name` のフル文字列へ変更し、`・` での切り詰めと `EngNameWithFlag` による `engName` 表示を外す。
- 既存の `FlagImage` を利用し、指定された左右の国旗配置を実装する。
- `matchData.titles.length` に応じた星列と、会場 `matchData.venue` を表示する。
- 必須情報の表示、空会場、タイトル数、アクセシビリティを検証するテストを追加・更新する。

### Out of Scope

- DB スキーマ、Laravel API、`MatchDataType`、`BoxerType`、試合・選手の登録編集フォームの変更。
- `displayNamePrimary` / `displayNameSecondary` などの表示名用カラム追加。
- `engName` や既存の `name` データ修正・正規化。
- 個別試合情報ページのレイアウト、団体タイトル詳細、勝敗予想の仕様変更。
- ホームカードからの直接投票、投票済み状態、勝敗予想結果の表示追加。
- 新たな Web フォント、背景画像、団体ロゴ、アニメーションの追加。

## Options

### Option 1: タイトル団体と試合グレードを下段に維持する

既存方針どおり WBA/WBC/IBF などの団体チップと `TITLE FIGHT` または `grade` をメタデータ帯に表示する。

メリット:

- タイトルの中身を一覧で即座に確認できる。
- 既存実装の一部を再利用できる。

デメリット・リスク:

- 小さい画面で情報が密集し、会場を置く余地がない。
- 星が表すタイトル数と団体チップが重複する。
- カードと詳細ページの情報階層が重複する。

### Option 2: 星でタイトル数を要約し、会場を表示する（採用）

団体チップと試合グレードを外し、`titles.length` 個の星でタイトル数を示す。下段の1枠を会場へ割り当てる。

メリット:

- 一覧では要点を短時間で読め、詳細な団体情報を個別ページへ自然に委ねられる。
- 会場は既存 `venue` で表示でき、データ層の変更が不要である。
- 星列は中央の `VS` を強めながら、タイトル戦の重要度を視覚的に伝えられる。

デメリット・リスク:

- 団体名を知るには個別ページを開く必要がある。
- 多数のタイトルが登録された試合では星の幅が増えるため、上限とアクセシブルな説明が必要である。

### Option 3: 下段を勝敗予想の状態表示にする

未投票なら投票を促し、投票済みなら予想分布などを表示する。

メリット:

- 参加を促し、ホームからの再訪動機を作れる。

デメリット・リスク:

- 試合情報を読んでから投票してほしい導線と競合する。
- ログイン・ゲスト状態・投票締切・集計公開状態の分岐がカードの主情報を複雑にする。
- 試合会場を表示する枠がなくなる。

## Decision

Option 2 を採用する。

カードは、日本語フルネーム、国旗、タイトル数の星、日付、階級、会場に情報を限定する。団体名、試合グレード、英字名、下段の投票CTAは表示しない。個別試合情報ページでタイトル団体の内容と勝敗予想を確認・操作する。

既存の `VoteIconForTop` は、将来試合かつ未投票という現在の通知機能として維持する。ただしカード下段へは移さず、カードの詳細遷移という主導線を妨げない。

カード全体は `type="button"` を持つ単一のボタン要素とする。クリックハンドラーだけで既存の `onClick(matchId)` を呼び、Enter/Space の操作はネイティブのボタン挙動に委ねる。重複発火を避けるため、個別の `onKeyDown` は追加しない。

タイトル数が0件の非タイトル戦では星列を描画しない。1件以上では星を `titles.length` 回描画し、スクリーンリーダー向けに「{n}団体タイトル戦」と説明する。想定を大きく超える数のタイトルが実データに存在する場合は、実装前に星数を最大表示数へ丸める別仕様を承認する。本タスクではデータを忠実に全数表示する。

## Rationale

- 選手名を `name` のまま使うため、英字名の分割規則や表示名専用カラムが不要になり、誤った姓名分割を避けられる。
- 星は「タイトルがいくつ懸かるか」という興味喚起だけを行い、詳細な団体名を個別ページで確認してもらう導線に合う。
- 日付・階級に会場を加えることで、一覧カードに必要な「いつ・どの階級・どこで」を完結させられる。
- `venue`、`weight`、`matchDate`、`titles` はすべて既存の `MatchDataType` にあり、backend/DBへの変更が不要である。
- 投票をカードで完結させないため、試合情報を確認してから投票する既存の体験を維持できる。

## Test Plan

### Component: `MatchCard`

- `redBoxer.name` と `blueBoxer.name` を、途中で切らずに表示する。`engName` は表示しない。
- 左右の国旗が各選手名の上に存在し、左選手は左寄せ、右選手は右寄せの配置用classを持つ。
- `titles` が3件のとき星を3個表示し、アクセシブルネームで「3団体タイトル戦」を取得できる。`titles` が0件なら星を表示しない。
- 団体名（例: `WBA`）と `TITLE FIGHT`、既存の試合グレードをカードに表示しない。
- 日付が英語短縮曜日を大文字で含む `YYYY.MM.DD DDD` 形式、階級が日本語の `{weight}級`、会場がピンアイコンとともに表示される。
- `venue` が空文字または空白だけの試合で、会場と会場用区切りが表示されない。
- 未投票の未来試合では既存の投票アイコンをカード左上 `12px` に表示し、左選手の国旗・名前は予約した `33px` の右に揃う。カード下段に投票CTAを追加しない。表示条件外ではアイコンも予約幅も表示しない。
- カードが `type="button"` を持つフォーカス可能なボタンであり、クリック・Enter・Spaceで `onClick(matchId)` を各1回呼ぶ。`onKeyDown` を設けず、キー操作が二重発火しない。

### Responsive / Manual Verification

- 320pxで選手名、`VS`、星、日付、階級、会場がカード内に収まり、ページとカードに水平スクロールが発生しない。
- 320pxで会場は日付・階級から独立した行にあり、会場名が長い場合も必要に応じて折り返されて読める。
- 767pxではSPの2行メタデータ、768pxではPCの1行メタデータへ切り替わる。
- PC幅で左国旗・左名前、右名前・右国旗の整列、角丸のない外枠、均等分割かつ中央寄せのメタデータ帯が崩れない。
- タイトル0件、1件、3件、4件、空会場、長い日本語名、長い会場名のサンプルを使い、情報の欠落・重なり・不自然な省略がないことを確認する。

## Risks

- 日本語フルネームと長い会場名が320pxで同時に長い場合、カード高が増える。選手名は情報識別に不可欠なため省略せず、会場名は自然な折り返しを許容する。
- 星だけでは個別団体名を識別できない。これは意図した情報階層であり、詳細ページで団体名を確認できることを目視確認する。
- `titles.length` が多い場合、星列が中央領域を圧迫する。現行の実データと4件までの表示を確認し、それを超える表示規則が必要になった場合は別途仕様化する。
- `venue` は既存データに空値・表記揺れがあり得る。カードではフォールバック文言を作らず、登録済みの値だけを表示する。
- `MatchCard` はホームと過去試合一覧で共有されているため、未来試合向けの投票アイコンや会場表示が過去試合一覧で不自然にならないかを確認する。
