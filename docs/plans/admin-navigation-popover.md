# Admin Navigation Popover

## Goal

管理者専用のページリンク集を、PC / SP ともにヘッダー内の常時表示から分離する。

管理者だけに表示する開閉ボタンを、PCではユーザーアイコンの左側、SPでは下段の通常ナビゲーション行の最右に配置する。押下時はヘッダー直下に管理ページへのリンク集を表示する。ログアウトアイコンは PC / SP ともに最右の配置を維持する。

## Background / Context

現在の実装では、管理者ページへの4リンクは次のように表示される。

- PC: `HeaderNavigation` 内で通常ナビゲーションの横にアイコンリンクを常時表示する。
- SP: ヘッダー右側のハンバーガーボタンから `MenuModal` を開き、その中にリンクを表示する。

PC はサイトタイトル、通常ナビゲーション、管理リンク、認証情報を同じ80pxのヘッダーに置いているため、画面幅によって要素同士が競合しやすい。今回採用するUIは、管理リンクを通常時は隠し、必要な時だけヘッダー直下に展開することでこの競合を防ぐ。

現行SPヘッダーは `h-[126px]` の固定高である。管理リンクパネルはヘッダーのレイアウト高には含めず、ヘッダー直下に重ねて一時表示する。そのため本文の `paddingTop` や `HEADER_HEIGHT` は変更しない。

PCヘッダー右側の最終的な並びは、認証済みまたはゲスト時に以下とする。

```text
[管理メニュー開閉] [ユーザーアイコン・ユーザー名] [ログアウト]
```

SPでは上段をユーザー情報とログアウトの領域として維持し、下段の通常ナビゲーション行の最右に管理メニュー開閉ボタンを置く。

```text
上段: [サイトタイトル] …………… [ユーザーアイコン・ユーザー名] [ログアウト]
下段: [Schedule] [Match Result] ……………………………… [管理メニュー開閉]
```

非管理者には管理メニュー開閉ボタンおよびリンク集を表示しない。

## Scope

### In Scope

- PC / SP 共通の管理メニュー開閉ボタンを追加する。
- 開閉ボタンをPCではユーザー情報の左、SPでは下段の通常ナビゲーション行の最右に配置する。
- PC ではボタンに紐づく右寄せのコンパクトなポップオーバーとして、ヘッダー直下にリンク集を表示する。
- SP では通常ナビゲーション行の下に、幅いっぱいのリンク集を表示する。
- 管理リンクは既存の `ADMIN_PAGE_LINKS` を唯一のリンク定義として使い回す。
- 既存の管理者判定を利用し、管理者だけにボタン・リンク集を表示する。
- リンク遷移、閉じる操作、キーボード操作を含む関連ユニットテストを追加・更新する。
- 管理リンクリストは `button`、`ul`、`Link` の標準的なHTML構造で実装し、ARIAの `menu` ロールおよび矢印キーナビゲーションは導入しない。

### Out of Scope

- 管理ページ、ルート、認証・認可API、バックエンドの変更。
- ログアウト処理および最右配置の変更。
- 新しいアイコン素材の作成・追加。利用可能な `react-icons` で代替できない場合の最終アイコン選定は実装開始前に確認する。
- ヘッダー以外の画面デザイン刷新。
- モーダル／ポップオーバーを同時に複数種類開ける共通状態管理基盤の導入。

## Options

### Option 1: ヘッダー直下のポップオーバー／展開パネル（採用）

管理者ボタンをPCではユーザー情報の左、SPでは下段の通常ナビゲーション行の最右に置く。PCではそのボタンの下に右寄せポップオーバー、SPでは通常ナビゲーション行の下に全幅パネルを表示する。

メリット:

- PCヘッダーで管理リンクが常時幅を消費しない。
- 管理機能への到達は1クリックのまま維持できる。
- SPでは既存の通常ナビの下に自然に収まり、タップ領域を確保しやすい。
- 現在の4リンクと既存のリンク定義をそのまま活用できる。

デメリット・リスク:

- 開閉状態、外側クリック、Escキー、フォーカスを設計する必要がある。
- SPでは表示中のパネルが本文に一時的に重なる。

### Option 2: 管理画面専用サイドバー

`/admin/*` 配下だけでサイドバーを常設する。

メリット:

- 管理画面内の画面遷移が明快で、機能増加にも対応しやすい。

デメリット・リスク:

- コンテンツ領域が狭くなるため、今回のUI方針に合わない。
- 一般画面から管理画面へ移動する導線が別途必要になる。

### Option 3: 管理トップページへの単一リンク

ヘッダーには「管理」へのリンクだけを置き、管理トップページで4機能を選ばせる。

メリット:

- ヘッダーの幅を最小限にできる。

デメリット・リスク:

- 目的の管理画面まで余分に1クリック必要となる。
- 新規の管理トップ画面とルートが必要になる。

## Decision

Option 1を採用する。

管理ボタンには `button` を使い、コンポーネントローカルの `useState` で開閉状態を管理する。今回のメニューは `Header` 内だけで開閉し、他コンポーネントから操作する要件がないため、Recoilのグローバル状態は新設しない。

ボタンには `aria-expanded` と `aria-controls` を設定する。これは開閉状態を管理するものではなく、`useState` で管理している状態を支援技術へ伝えるための属性である。

リンク集は `role="menu"` を使わない通常のリンクリストとする。開いた直後もフォーカスは開閉ボタンに残し、Tab / Shift+Tabでリンクを通常の順序で操作できるようにする。Escキー、パネル外のクリック／タップ、リンク遷移、開閉ボタンの再押下で閉じる。PC / SPともにパネルは絶対配置または固定配置でヘッダー直下に重ね、ヘッダー高には含めない。

## Rationale

- ユーザーが選んだ「ヘッダー直下に展開するリンク集」をPC / SPの各幅に合わせて実現できる。
- PCの横幅競合を、リンクを常時表示しないことで解消できる。
- ログアウトの最右配置を保ち、既存の認証・ログアウト責務に影響しない。
- 既存の `ADMIN_PAGE_LINKS` を利用するため、リンク追加・パス変更時の更新箇所を増やさない。
- 管理メニュー専用のローカル状態にとどめることで、既存のSP全画面 `MenuModal` の状態と不要に結合しない。

## Test Plan

追加・更新するユニットテストでは、実装詳細ではなく次の振る舞いを保証する。

- 管理者には「管理メニュー」ボタンが表示され、非管理者には表示されない。
- 管理ボタンを押すと4つの管理ページリンクが表示され、再度押すと閉じる。
- 開いた状態ではボタンの `aria-expanded` が `true`、閉じた状態では `false` になる。
- 各リンクは既存のパスへ遷移し、クリック後にメニューを閉じる。
- Escキーとパネル外クリックで閉じる。
- Tab / Shift+Tabで、開閉ボタンとリンクを通常のフォーカス順で操作できる。
- PCでは通常ナビ内に管理リンクが常時表示されない。
- PCでは管理ボタンがユーザー情報より左、ログアウトボタンより左に配置されることを確認する。SPでは下段通常ナビゲーション行の最右に配置され、上段のユーザー情報・ログアウトと競合しないことを確認する。
- 現在ページの管理リンクに `aria-current="page"` を設定し、現在地を明確にする。
- SPの展開時に本文へ一時的に重なること、閉じた後に通常どおり本文を操作できることをブラウザで確認する。
- PC / SPの切替時にメニューが閉じ、既存のヘッダー高が変化しないことを確認する。

## Risks

- `useAdmin()` の取得中にボタンが後から表示されるため、PCでは認証情報付近、SPでは通常ナビゲーション行の右端に小さなレイアウト変化が起こり得る。必要なら管理ボタンと同等幅の領域を確保する。
- 表示中のパネルは本文の先頭や操作要素に重なる。パネル外クリック／タップ、Escキー、リンク遷移で確実に閉じられることを確認する。
- 外側クリック判定がボタン押下イベントと競合すると、開いた直後に閉じることがある。ボタンとパネルを同じ参照範囲として扱う。
- 小さいSP幅では下段の通常ナビゲーションと管理ボタンが同居する。通常ナビの各リンク幅、管理ボタンのタップ領域、上段のユーザー名省略表示を実機幅で確認する。
- 旧 `MenuModal` を削除する場合、管理リンク以外の用途、AppShellでのグローバルマウント、ログアウト処理との連携を見落とすと回帰する。削除はPhase 4で参照箇所を確認してから行う。
