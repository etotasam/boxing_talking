# P6完了後の計画文書整理

## Goal

計画一覧から現在の残課題を確認でき、完了したP6の検証結果と再監査の根拠を履歴から辿れる状態にする。

## Background / Context

P6は承認された縮小範囲の検証、独立レビュー、専用環境の整理まで完了した。再監査報告は2026年11月2日の記録で、依存更新候補や運用課題は全体計画に引き継がれている。P4とP6は全体計画で完了済み。P4jの監査指摘2件はユーザー判断で未対応のまま終了した。

## Scope

- P4j調査、P6最終統合検証、最終監査報告に結果を追記し、元の日付とファイル名で `archive/dependency-runtime/` に移す。
- 計画一覧と関連する参照リンク・パスを更新する。全体計画を現在の入口にする。
- アプリ、環境、監査証跡、依存更新、再監査、本番作業は対象外。

## Impact Area

`docs/plans/` の計画一覧、全体計画、移動対象の3文書。

## Approach / Rationale

配置を維持して目次の状態だけ更新する案と、実施記録を既存の分類へ移す案を比較した。後者なら現在の目次を継続課題に絞り、検証範囲・当時の判断・監査結果も原文で参照できる。P4jの未実施項目は未チェックのまま維持し、承認済みの検証範囲での完了と当初の広い検証範囲を明記する。P4jの再評価条件、Symfony Mime、本番確認、定期DBバックアップを現在の入口から辿れるようにする。

- [x] ユーザーが移動・参照整理を承認した（「archiveにまとめてくれ」）。

## Test Plan

- 移動前後の原文を比較し、既存の検証範囲や未確認事項が保持されていることを確認する。
- 移動先、リポジトリ内の旧パス参照、変更した相対リンクと見出し、`git diff --check` を確認する。
- Markdownのみの変更のため、アプリテストとビルドは省略する。

## Risks

- P6の履歴化で当初の検証範囲全体が完了したと読める可能性がある。承認済み範囲での実績と、全画面・メール全体・本番の未確認範囲を結果に明記する。
- 結果にはqueueのP5証跡再利用とNode更新記録への参照も残す。全体計画の進捗表は専用環境の削除実績と揃える。
- 文書移動により相対リンクの基準が変わるため、移動元と移動先双方の参照を検査する。

## Outcome

- P4j調査、P6最終統合検証、最終監査報告を既存の依存・実行環境更新の履歴へ移動し、[計画一覧](../../README.md)と参照先を更新した。
- 移動前の原文と照合し、検証範囲・未確認事項・再評価条件を保持したことを確認した。最終配置で相対リンクと見出し69件を確認し、`git diff --check` は成功した。文書のみの変更のため、アプリテストとビルドは省略した。
- 最終レビューで必須指摘なし。P4jの候補再解決・監査・更新案の作成はユーザー判断で見送り、未チェックのまま移動した。開発依存の監査指摘2件、Composer Mime、本番確認、定期DBバックアップの扱いは[全体計画の残課題](../../2026-10-22-dependency-runtime-update.md#残課題)を参照。
