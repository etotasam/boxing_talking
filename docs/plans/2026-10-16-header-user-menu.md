# ヘッダーの名前付きユーザーメニュー（A案）

## Goal

ログイン後のヘッダーを「丸いユーザーアイコン＋名前＋下向き矢印」にまとめ、クリックで「ログアウト」だけを含む小さなパネルを開く。ユーザーが選んだ画像A案の控えめなデザインを実現する。

## Background / Context

- A案と主要ケースに絞ったテスト方針についてユーザー承認を得て実装済み。検証結果は末尾に記載する。
- `HeaderAuthInfo.tsx` はアイコン・名前を表示し、独立したアイコンボタンでログアウトする。PCでは間に縦の区切り線がある。
- `useHeaderAuthInfo.ts` は通常ユーザーなら `logout`、ゲストなら `guestLogout` を返す。ユーザーでもゲストでもない場合はnullを返す。
- 現在の通常ユーザーのアイコン背景はシアン、ゲストはグレー。A案では両方とも控えめなグレーへ統一し、名前（ゲスト時は「ゲスト」）を残す。
- 未ログイン時のログインモーダル自動表示は `layout/AppShell.tsx` が担当している。今回この挙動は変更しない。
- `HeaderView.tsx` はPC・SPで配置を切り替え、管理者の場合は下段ナビゲーションも持つ。固定ヘッダーの高さを変えない。
- 既存のヘッダーポップオーバーに外側pointerdown・Esc・イベント解除の実装例がある。参考にするが、既存メニューの共通化や改修は行わない。

## Scope

### In Scope

- 通常ユーザーとゲストのアイコン・名前を、単一の開閉ボタンにする。独立したログアウトボタンとPCの縦区切り線を外す。
- PC・SPとも名前付きトリガーと、ログアウト1項目のパネルを使う。
- 開閉、外側クリック、Esc、フォーカス移動、ログアウト選択を実装する。
- 関連する表示・操作テストを更新する。

### Out of Scope

- ログインモーダル、認証判定、ログアウトAPI、キャッシュ削除、ローディング・失敗通知・成功後の遷移の変更。
- プロフィール、予想一覧、設定などのメニュー項目追加。
- 管理者メニューや一般ページメニューの設計変更・共通化、新規依存パッケージの追加。
- 画像案のヘッダー全体の再現、ロゴ・ナビゲーション・カードの変更。

## Impact Area

- 主な実装: `frontend/src/components/module/Header/component/HeaderAuthInfo.tsx`
- 表示用データ: `frontend/src/components/module/Header/hooks/useHeaderAuthInfo.ts`（背景色の統一と不要になる表示用props整理のみ。認証・ログアウトの分岐は維持）
- 主なテスト: `frontend/src/components/module/Header/__test__/HeaderAuthInfo.test.tsx`
- 必要時のレイアウト調整: `frontend/src/components/module/Header/component/HeaderView.tsx`。メニューが切れる・隠れる場合の最小限の幅・重なり調整に限定する。
- 回帰確認: Header関連テスト、既存の `useLogout`・`useGuestLogout` テスト。
- バックエンド、API、DB、環境変数への変更はない。

## Options

1. 現状の独立したログアウトボタンに文字を添える。
   - 操作が直接的だが、ユーザーの希望する整理やA案の構成を満たさず、横幅も増える。
2. A案の名前付きトリガーから、通常のボタンを含む小さな開閉パネルを表示する（採用）。
   - 既存の認証処理を維持でき、ログアウト1項目に適した小さな変更。外側操作・フォーカスの扱いを実装する必要がある。
3. `role="menu"` / `menuitem` を持つ本格的なメニューを実装する。
   - 複数項目や矢印キー操作に拡張できるが、今回は1項目のため専用のキー操作やフォーカス管理が過剰になる。

## Decision

案2を採用する。見た目はポップアップメニュー、操作上はボタンで開閉する非モーダルのパネルとする。

### デザイン

- トリガー: 枠なし・透明背景、グレーの丸い背景に白いユーザー線画、名前、控えめな下向き矢印。既存のreact-iconsを利用する。
- A案どおりモノトーンを基本とする。ホバー・展開時は背景や文字の明度を少し変え、フォーカスには見えるアウトラインを設ける。ゴールドへの変更は今回追加しない。
- 追加承認に基づき、ユーザーアイコンはSP28px・PC32px、名前はSP11px・PC14pxの通常ウェイト、間隔は6pxとする。トリガーの操作領域は高さ44px以上を維持する。パネルのサイズは変更しない。
- パネル: 幅約180px、暗いチャコールの不透明背景、薄いグレーの1px枠、約6pxの角丸と弱い影。右端をトリガーに合わせ、直下に約8pxの間隔で絶対配置する。
- 項目はログアウト線画＋「ログアウト」。通常は白系、ホバー・フォーカスで薄い背景を付ける。危険操作の赤色や追加の確認モーダルは設けない。
- PC/SPとも名前を残す。長い名前は省略表示し、支援技術からは完全な名前が分かるようにする。320px・375px幅でもロゴと矢印が押し出されない幅制約を設ける。
- パネルはヘッダーの高さや本文の位置を動かさず、管理者ナビゲーションより手前に表示する。既存モーダルの重なり順を妨げない。
- 初回実装は開閉時に条件描画し、退場アニメーションによる非表示要素のフォーカス残存を避ける。

### 操作・アクセシビリティ

- 初期状態は閉。トリガークリックまたはEnter/Spaceで開閉する。名前のクリックでログアウトしない。
- トリガーには `type="button"`、`aria-expanded`、一意な `aria-controls`、名前を含む識別可能なアクセシブルネームを付ける。装飾アイコンは読み上げ対象外とする。
- パネル内は通常のログアウトボタンとし、`role="menu"` / `menuitem` / `aria-haspopup="menu"` は使わない。専用の矢印キー操作やフォーカストラップは設けない。
- 開いた直後のフォーカスはトリガーに置き、Tabでログアウトへ進める。Shift+Tabでも通常の順序で移動できる。
- 外側pointerdown、Esc、トリガー再クリックで閉じる。Escではトリガーへフォーカスを戻す。外側クリックではクリック先のフォーカスを奪わない。
- フォーカスがトリガーとパネルの両方の外へ移った場合も閉じる。閉状態のログアウトはDOMに存在せず、Tabで到達しない。
- ログアウト選択時は、パネル内にフォーカスがある場合にトリガーへ戻してからパネルを閉じ、既存の `onLogout` を1回呼ぶ。通常ユーザー・ゲストの既存分岐、成功・失敗時の挙動は変えない。失敗時は再び開いて再試行できる。
- 認証情報がなくなるとパネルも消える。ユーザー表示の切替やPC/SP切替時に開いた状態を持ち越さない構成にする。ルート遷移時にも閉じる。
- 開閉用のdocumentイベントは必要時だけ登録し、閉じる時・アンマウント時に解除する。

## Rationale

ユーザーが選んだA案に合わせ、名前付きの1つの操作へまとめる。ログアウト処理を既存hookへ委ねることで、変更を表示とパネル操作に限定できる。1項目のため通常のボタンとTab操作が理解しやすく、追加ライブラリなしで検証できる。

## Test Plan

実装時に `.agents/skills/tester/SKILL.md` と `frontend-test/SKILL.md` に従う。CSSクラスや内部stateではなく、表示・操作結果を保証する。

### Vitest

- PC/SPの通常ユーザーとゲストで名前付きトリガーを表示し、初期状態ではログアウト項目を表示しない。
- トリガーを押すとログアウトが1件表示され、`aria-expanded` が変わる。再クリックで閉じ、開閉だけではログアウトしない。
- ログアウト選択時、通常ユーザーは `logout` のみ、ゲストは `guestLogout` のみを1回呼び、閉じる。
- キーボードでログアウトを選択した後も認証情報が残る場合、トリガーにフォーカスが戻ることを保証する。
- 外側クリックとEscで閉じること、Escのフォーカス復帰と外側操作のフォーカス維持を保証する。
- キーボードのテストは、Enter/Spaceで開き、Tabでログアウトへ移動し、Esc・ログアウト後にフォーカスが戻る主要操作に絞る。追加承認に基づき再オープン・閉状態のTab移動の確認と、Tabで外へ移ると閉じる独立テストは削除する。実装の挙動は変更しない。
- ユーザーでもゲストでもない場合はトリガーを表示しない。
- 自動テストは上記の主要操作に絞る方針をユーザー承認済み。認証情報消失、表示ユーザー切替、PC/SP切替、ルート遷移をすべて独立したテストとしては追加しない。PC/SP切替時の閉鎖は実画面で確認する。
- 既存のログアウト成功・失敗時のhookテストを実行し、既存処理を維持できていることを確認する。

実行予定（frontend内）:


### 画面確認

- PCとSP（320px・375px幅）でA案の見た目、長い名前の省略、文字と矢印の収まりを確認する。
- 管理者の下段ナビゲーションがある画面でもパネルが隠れず、本文やヘッダーが動かないこと。
- ポインター・タッチ・キーボードで開閉とログアウトを確認し、ログアウト後は既存のログインモーダル導線へ戻ること。
- 開いた状態で別のヘッダーメニューを操作した時、ユーザーパネルが外側操作で閉じること。
- 表示名が空の場合でも、トリガーには「ユーザーメニュー」等の判別可能な名前を持たせる。

## Risks

- SPではロゴと長い名前が幅を奪い合う。トリガーと名前の幅を制約し、既存ヘッダー高は維持する。
- 固定ヘッダーの重なり順によりパネルが下段ナビゲーションに隠れる可能性がある。実画面で確認し、必要な最小限の調整を行う。
- フォーカス移動と外側pointerdownの順序により、ログアウト前にパネルが閉じないようコンテナ内外の判定をまとめる。
- 既存テストはログアウトが常時表示される前提のため、新しい開閉操作へ更新する必要がある。
- API呼び出しや失敗時の通知は既存仕様を引き継ぐ。今回新たな認証フローは追加しない。

## Design Review

- Reviewer subagentの評価: 設計方針・影響範囲・既存認証処理の維持・テスト方針は妥当。必須指摘1件を反映した。
- 反映内容: ログアウト選択でパネルを閉じる前に、パネル内のフォーカスをトリガーへ戻す仕様と、認証が残る時にキーボードで再操作できるテストを追加した。
- 残リスク: 320px幅での配置と実画面の重なり順は実装後に検証する。

## Implementation Results

- 実装・テストをメインエージェントで担当し、Reviewer subagentによる実装レビューは問題なし、必須修正なし。
- `HeaderAuthInfo.tsx` と表示用hook・既存テストを変更。認証処理・API・HeaderViewの変更なし。
- A案のグレーの丸いアイコン・名前・矢印と、ログアウト1項目のパネルを実装。ログアウトの線画には出口の形が分かる `IoLogOutOutline` を採用した。
- レビュー後の最終検証で関連Vitestは11ファイル37件成功（今回のHeaderAuthInfoは8件）。lint・build・`git diff --check` も成功。
- VitestはVite WebSocket待受のEPERMログとReact Routerの将来仕様警告を伴うが、全テスト実行・終了コード0。buildにはBrowserslistデータの古さとchunkサイズの警告あり。
- PC・375px・320px幅で確認。通常ユーザー（管理者）・ゲストのパネルが画面内に収まり、管理者下段より前面に表示され、ヘッダー高・本文の位置は変わらない。320pxでは既存のロゴ省略が適用される。
- PC/SP切替でパネルが閉じることを実画面で確認。通常ユーザー・ゲストとも実際のログアウトから既存のログインモーダルへ戻ることを確認した。
- 画面確認中に管理者の一般ページボタンを操作しようとした際、上に重なったログアウト項目をクリックして通常ユーザーをログアウトした。その後ゲスト表示を確認。確認終了後は未ログイン状態に戻し、元の表示幅に復元済み。
- 長い名前の実画面は未確認。名前の最大幅と省略表示、完全な名前を含むアクセシブルネームを実装済み。ユーザー切替等の全条件を網羅するテストは承認済み方針に従い追加していない。
- 追加承認の小型化を反映。PC32px/SP28pxのアイコン、PC14px/SP11pxの名前、6px間隔に変更し、操作領域44pxとパネルの寸法は維持。PCと375px幅で見た目を確認し、関連8テスト成功、Reviewer指摘なし。表示幅は復元済み。
- 追加承認によりキーボードテストを主要なフォーカス復帰に絞り、Tabで外へ移る独立テストを削除。HeaderAuthInfoのテストは8件から7件となり、全7件成功、`git diff --check` 成功、Reviewer指摘なし。実装コードは変更していない。
