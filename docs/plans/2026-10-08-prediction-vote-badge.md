# 勝敗予想受付バッジの配置・表示変更

## Goal

B案を基に、勝敗予想の投票が可能な未投票の試合カードで、VSの下に「勝敗予想受付中」と表示する。文字で意味を伝え、黒・ゴールドの既存デザインに合わせる。

## Background / Context

- 現在は `MatchCard.tsx` の日付欄にゴールド背景の投票アイコンを表示している。
- `useVoteIconState` が表示可否を判断している。予想データ取得前、試合当日・過去、投票済みの場合は非表示となる。
- カード全体が試合詳細を開くボタンであり、バッジは独立した操作要素ではない。
- ユーザーと合意したテスト方針は、表示判定結果に応じた表示・非表示の確認。配置は画面で確認する。
- この文書は実装承認前の提案であり、実装コード・テストはまだ変更しない。

## Scope

### In Scope

- 日付横のアイコンを、VS直下の文字バッジに置き換える。
- 文言は空白を挟まず「勝敗予想受付中」とする。
- 薄いゴールドの枠、角丸、暗い背景、ゴールドの文字を用いる。
- PC・スマホで文字サイズと余白を調整する。
- 既存の表示条件を利用し、関連テストの表示内容と旧配置に依存する確認を更新する。

### Out of Scope

- 表示判定hook、API、バックエンド、投票フローの変更。
- カードのクリック動作、日付・階級・会場表示の仕様変更。
- 判定hook自体の新規テストや、配置・CSSクラスを固定する自動テストの追加。

## Impact Area

- 実装: `frontend/src/components/module/MatchCard.tsx`
- テスト: `frontend/src/components/module/__test__/MatchCard.test.tsx`
- 同じカードを利用する画面のPC・スマホ表示に影響する。非表示条件の試合ではバッジを出さない。
- API、DB、設定値、依存パッケージへの影響はない。

## Options

1. A案: カード上部に受付状況の行を追加する。意味は明確だが、カードの高さと情報量が増える。
2. B案: VS直下に文字バッジを置く。対戦を見る視線で認識でき、既存構造を活用できる。スマホで中央列の幅と余白に注意が必要。
3. C案: カード下部に参加導線の行を追加する。行動を促しやすいが、行が増え、今回のバッジ変更より修正範囲が広い。

## Decision

B案を採用する。文言は「勝敗予想受付中」。現在の中央列の星・VSに続けて条件付きでバッジを描画し、日付欄からアイコンを外す。

## Rationale

ユーザーが選んだB案を、表示条件を変えず小規模なUI修正で実現する。画像は拡大モックなので、その文字サイズやカード高さをそのまま再現せず、既存一覧に収まるサイズへ調整する。

## Test Plan

### 自動テスト

- `useVoteIconState` をtrueにした場合、「勝敗予想受付中」が1個表示されること。
- falseにした場合、同文言が表示されないこと。
- 既存のPC・スマホ切替テストでは新しい文言を参照し、重複しないという既存の確認を維持する。配置を確認する新規テストは追加しない。
- 日付欄の中にバッジがあることを確認する既存assertionは削除する。
- カードクリックと日付強調など、今回と無関係な既存テストは維持する。
- これらは判定結果に従ったカードの表示を保証する。実際の投票情報・日付からの判定ロジック自体は今回の検証範囲に含めない。
- 実装後、frontendで `npm test -- --run src/components/module/__test__/MatchCard.test.tsx`、`npm run lint`、`npm run build` を実行する。実行できない場合は理由を報告する。

### 画面確認

- PC・スマホでバッジがVSの下に収まり、星・VS・選手名・日付欄と重ならないこと。
- スマホの狭い幅と長い選手名でも、バッジが中央列を過度に広げず、内容が欠けないこと。必要なら文字サイズ・余白を小さくする。
- タイトル戦・非タイトル戦、表示・非表示のカードで中央の配置が自然であること。
- カード内に追加の操作要素を作らず、バッジ部分を含めたクリックで従来の詳細表示につながること。

## Risks

- 中央列の幅が増えると選手名が折り返しやすくなる。狭い画面で文字サイズ・余白を調整する。
- バッジがあるカードは高さが増える可能性がある。固定高や非表示時の空バッジは設けず、既存の可変レイアウトで余白を確認する。
- 旧aria-labelで検索するテストが残ると失敗するため、関連する既存テストをまとめて更新する。

- 関連Vitest: 8件成功。Reviewer subagentによる実装レビューは問題なし。レビュー後の関連テストも成功。
